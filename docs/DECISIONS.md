# Decisions

Add one line here whenever we make a choice or something surprises us. Move requirement IDs between phases only through a decision recorded here.

## Decided

1. **No dedicated brain PC.** A desktop app on each staff PC does the voice loop, search, files and outbox. A small cloud gateway handles the language model. Why: nobody has to own or set up a shared machine.
2. **Python backend, Tauri desktop shell, browser-tech UI.** Why: best ML library support, one UI codebase.
3. **The language model outputs a validated plan, never direct actions.** Why: safety and testability.
4. **Confirmation required for external sends and deletes.** Why: speaker ID is not strong authentication.
5. **Gemma 4 is the language model, called through an API.** Supervisor's choice. Default is 26B A4B through the gateway. Why: cheapest and fastest of the large models, native function calling, no GPU to run ourselves.
6. **Local profile (on-device Gemma 4 E4B or E2B) is later, not MVP.** Why: needs more RAM than most staff PCs have, and quality on small models must be tested first.
7. **Minimum 8 GB RAM per staff PC.** A 2 GB machine cannot run the app locally.
8. **Keep Whisper for speech-to-text** until a test shows Gemma 4 audio input does better on Nigerian-accented English.
9. **RAG for policies, circulars and summaries, with cited answers.**
10. **Use the existing `ILEMONAcodes/ARIA` GitHub repository.** Initialize the supplied project pack on `main` and connect it as `origin`; do not create a second repository.
11. **Document the backend file architecture before expanding the skeleton.** `docs/ARCHITECTURE.md` separates existing starter files from planned phase A–I modules, defines runtime/security boundaries and lists phase gates. Planned modules are created only when their phase is reached; the UI contract remains unchanged.
12. **Phase A uses a uv workspace and one committed lockfile.** Keep the agent and gateway as separate packages, share a Python 3.11 development environment, and run the same lint, format, type, offline unit-test and contract checks locally, in pre-commit and in backend CI. Later deployment workflows will adopt the lockfile when their packaging is implemented.
13. **Agent configuration uses TOML with environment overrides.** Explicit `load_settings(path)` reads an `[agent]` table; known `ARIA_*` variables override file values, which override defaults. File paths are relative to the file; environment/default paths are relative to the working directory. Installation tokens are environment-only, excluded from serialization, and validation errors omit supplied values. Gateway URLs require HTTPS without embedded credentials, queries or fragments. An unconfigured gateway stays unset; loading settings never contacts a service or creates storage. SQLCipher key access is limited to the planned OS vault. The gateway keeps its separate environment-only configuration.
14. **Local diagnostic logs contain metadata only.** The `aria.agent` logger writes UTC JSON to stderr (or an injected stream) with approved event names, UUID task IDs and finite nonnegative durations. It omits messages, formatting arguments, exceptions and arbitrary extra fields; unknown metadata becomes a safe fallback. User-readable activity history remains separate. Real-agent startup wiring follows in A4; these modules do not change the mock or UI contract.
15. **Phase A storage requires SQLCipher 4 and native vault keys.** Use the upstream `sqlcipher3` driver, verify encryption support before opening a user file, and validate the key by reading the schema before migrating. Store randomly generated 256-bit keys through native Windows Credential Manager or macOS Keychain backends; reject plaintext, fallback and unavailable backends. Key records use a hash of the resolved database path, so moving/restoring a file requires its matching original vault key; never create a replacement key for an existing file. A file lock serializes first-key creation and upgrades. Tests use fake vaults with real SQLCipher and no real credentials.
16. **Migrations and history retention are transactional.** Start with profiles, settings, transcripts and activity tables; later feature tables arrive with their phases. Ordered migrations record checksums and reject changed, missing or newer history. Timestamps use UTC integer microseconds. Each database open purges transcripts older than 30 days and activity older than 90 days atomically; exact boundaries are retained. A4 adds recurring cleanup to the real-agent lifecycle. SQLCipher encrypts storage and journals, temporary data stays in memory, and secure deletion is enabled; retention does not promise removal from external backups.
17. **A4 separates adapter interfaces from startup assembly.** Use typed protocols for audio capture, VAD, wake detection, STT, speaker identification, speech output, planning, LLM calls, network status, clocks, keys and storage. Reuse the existing Tool abstraction and UI speaker/plan models without changing the contract. Internal request values separate instructions from source data blocks; prompt rendering and provider routing remain phase C work. Fakes are deterministic, in-memory and explicit; they are never a fallback for failed production adapters. Shared history/retention values move to interfaces while retaining their prior import paths.
18. **Startup owns cleanup and recurring retention.** `start_agent` loads settings, configures content-free logs, opens encrypted storage, prepares injected components, and runs a daily retention task. Components close in reverse order; the worker stops before storage closes, including cancellation and partial startup failures. The foundation CLI supports `--check`, `--settings` and explicit `--fake` mode. Default startup uses native vault-backed SQLCipher and leaves unimplemented voice/model adapters absent; fake mode uses memory only. No microphone reads, cloud calls, computer actions or HTTP/WebSocket serving occur during this foundation check. Startup/cleanup errors are sanitized, and failed retention is logged without content and retried on the next interval.
19. **Windows unit tests allow only asyncio's internal socket pair.** CI showed Python 3.11's Windows event loop needs a TCP loopback pair before application startup. A test-only factory creates that pair on numeric `127.0.0.1` with an ephemeral port; ordinary socket creation and DNS remain blocked by pytest-socket. It does not enable service or Internet connections for application code. IPv4/IPv6 guard tests verify the restriction remains in place. Unix platforms retain their existing Unix-socket allowance.
20. **A5 generates TypeScript without scaffolding the frontend app.** Pin json-schema-to-typescript and TypeScript in an isolated pnpm tool package under `scripts/contract`; emit generated models into the existing desktop contract directory. Public exports include strict wire-envelope helpers requiring the version and discriminator, while raw types retain Pydantic defaults. Compile every scenario event/response plus consumer and negative examples. Keep the Pydantic event schemas and contract version unchanged. Backend CI and a scoped pre-commit hook reject stale artifacts and compile errors; the frontend can delegate its eventual `gen:types` command to this tool.
21. **The mock now enforces the documented transport and approval rules.** Validate the entire replay, including wait event names, versions, delays and correlated approval examples. Require a per-session token for WebSocket and health access, bind only to localhost, suppress request logs, and reject malformed/unsupported messages. Wrong IDs do not advance replay; matching declines and cancellation stop it without fictional success events. Confirmation accepts click or key, never voice. This fixes development-fixture behavior without changing event fields or implementing real actions. `FRONTEND_HANDOFF.md` documents the transition from the unauthenticated starter mock.
22. **Verify the live handoff separately from unit tests.** Unit tests keep sockets blocked and replay all four scenarios in-process. `scripts/smoke_mock.py` additionally starts its own temporary localhost mock process, checks authenticated health, completes the policy WebSocket replay with fictional data, and always stops that process. Proxy use is disabled; no external service or real user data is involved. This separate integration check runs in backend CI.
23. **Clarify the Phase A gate against the role guide.** Foundation completion means green backend/contract CI, a running mock, and generated types that compile. The unscaffolded desktop UI is frontend F0 work. The earlier file map's real `api/` entry was marked A prematurely; real-agent transport belongs with B's VOX-1–4/SYSX-1 voice integration. No requirement IDs move phases, and A5 does not claim a real voice/request-serving loop or deployment readiness.
24. **Browser mock health checks use explicit CORS origins.** `--allow-origin` enables GET/Authorization preflight for a frontend's actual origin; it is disabled by default and rejects wildcards. The health request itself still requires the session token. This supports F0 without guessing or fixing the UI port and does not change event schemas.

25. **Build Phase B's pipeline before collecting voice assets.** The user has no trained HeyAria model or consented recordings and asked to build the pipeline first. Add local-only Windows CPU adapters behind the existing interfaces, bounded in-memory audio, PTT, optional custom wake activation, segment partials, spoken echo and stop/cancel. Missing assets fail closed; no runtime downloads or fallback fakes. Keep native dependencies in an opt-in Windows `voice` group and verify imports separately in CI. Store no echo transcript/audio; emit session activity without guessing a profile. Keep the foundation storage CLI separate from `agent.voice` until identity/task integration exists. Reuse v1 events without schema changes and keep Phase B's hardware, UI, latency, WER and wake false-accept gates pending. The Piper runtime and individual voice licenses must accompany future packaging review.

26. **Defer voice assets and real speech evaluation at the user's request.** The user asked to put speech-model setup, HeyAria training and real voice testing on the later-work list and move on. Track the outstanding tasks in ROADMAP.md; Phase B remains incomplete and its requirements remain MVP requirements. Permit independent Phase C planner/gateway/router implementation with text inputs and fake adapters before the B gate passes. Return to the deferred voice tasks after that implementation, or earlier on request, and require their acceptance checks before the MVP pilot/release. This is a sequencing exception, not a waiver of speech accuracy, latency, privacy, confirmation or frontend integration gates.

27. **C1 validates plans without execution or public contract changes.** Harden tool registration, capture immutable policy metadata, forbid duplicate tool names, and validate untrusted plans/arguments strictly with registered risk and network requirements as authority. Reject invalid plans with content-free errors and return clarification state for low confidence, missing slots or empty steps. Keep v1 models/generated schemas unchanged. Result bindings fail closed until the executor resolves and revalidates them; approval, timeouts, retries, grounding and runtime wiring remain later C work. Require Pydantic 2.12+ for per-call extra-field enforcement. The user-authorized voice deferral remains recorded in decision 26.
